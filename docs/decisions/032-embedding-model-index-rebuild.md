# 032 · Embedding 模型切换与检索索引重建

日期：2026-10-04。基于f26e2a8。用户要求使用一段时间后能更换Embedding并重建已有索引。

## 旧实现与取代范围

此前保存Embedding时实际会对全部parser_version非空资料调用source_ingest重试，
但没有专用批量状态/失败入口，同模型保存也排队；旧解析版本或图片失败会触发重解析/
识图。此前交互中“没有自动触发”的判断已更正，不把已有行为说成新实现。
032取代该保存后重处理路径，保留原索引原子发布、历史引用稳定及029并发预约。

## 契约与实现

模型测试成功后，在model_configs写事务内调IndexRebuildService为当前Notebook关联的
已解析有文字资料排source_reindex，共享资料只一次；不自动发送解绑/未解析/无文字项。
失败测试不保存、不排队；相同有效配置或密钥轮换不重算，有缺失/过期项仍可补齐。
任务直接重建chunks/chunk_blocks/embeddings，不重解析或OCR，不修改资料原件、段落、
引用、既有问答、知识页、Deck、render/PDF。使用持久队列、资料写预约、两批Embedding
内部并发及服务总请求额度；重启恢复，失败保留已存在索引与成功兄弟项。

新模型配置身份包含base_url/model_id/dimensions，保存在Embedding capabilities的
index_signature字段，最终索引签名另包含当前CHUNKER_VERSION。旧配置无该字段时
继续用历史模型ID/维度/chunker签名；相同配置测试保留legacy兼容身份。地址/模型/维度
变化才转到新身份；API Key/上下文预算不决定向量空间。无需迁移或升级自动重建。
服务端同名模型实际变化无法自动探测，提供明确“重新计算全部索引”。
该操作在事务内建立新索引身份再排队，失败仍保留旧向量但不得混用旧空间与新查询；
当前重建已在排队/运行时重复全量请求不另起版本。失败重试沿用本次身份。
旧程序不理解source_reindex与新配置身份；回退需使用对应旧代码和完整清理前数据，
不能因schema编号未变就直接把新模型配置的数据交给旧程序。

生成向量后、删除旧chunks前，BEGIN IMMEDIATE内对当前配置签名复核。连续换模型在
同一事务更新唯一活动job的payload目标；queued用最新配置，running待请求结束后丢弃
旧结果并继续最新配置，不放宽jobs活动唯一约束，不通过取消未join任务解锁资料。
旧模型向量仍保存到新版成功但不能参与新模型检索。未就绪问答提示去模型设置。

GET `/api/settings/models/embedding/indexes`返回当前签名的总数/状态和各资料名称、
进度、安全错误码；POST `/rebuild`有missing、failed、all模式，活动项去重。状态从
真实索引与持久job推导，不引入可漂移的批次统计表。设置中每2秒刷新，关窗停止轮询；
后台继续执行，12语言一致。重建的文字发送与费用提示在操作前显示。

## 验证

隔离模拟模型验证实际切换、维度/地址变化、相同模型/密钥轮换、原文/引用保留、失败
原子保留/重试、连续/排队切换、共享/解绑资料、源删除保护和正常重启恢复。
浏览器验证设置保存、逐项失败与重试、关窗继续、刷新和手机布局；不以mock断言真实
检索模型质量或实际重建速度。完整检查与本地发布证据见[ACCEPTANCE](../ACCEPTANCE.md)。

## 2026-10-04补充：重新关联资料

未关联资料不参加模型切换重建的范围保持。重新关联时按当前身份只补排该资料缺失/过期
索引，有效索引跳过，重复关联去重活动任务；不重新解析文件或OCR。此缺口在034的
语言回归中发现并修复，验证与发布见ACCEPTANCE。
