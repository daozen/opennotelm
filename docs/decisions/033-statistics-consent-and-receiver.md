# 033 — 统计参与选择与接收服务配置

日期：2026-10-04。背景：用户报告匿名统计无法勾选，并询问开源项目接收服务由谁配置。

## 实际修复

前端曾在configured=false且enabled=false时禁用开关，后台却独立保存用户选择；
当前部署token为空，因此触发该条件。移除此条件，加载/保存时仍禁用；成功PUT返回
是权威偏好，不再以第二次GET决定成功，失败恢复原值并允许重试。新增12语言保存反馈
及未接收时本地暂存提示。没有修改发送策略、启用生产偏好或创建任何外部统计项目。

已有发送契约继续：默认关闭、显式同意才捕获，无接收配置不发送；队列最多1000条、
7天过期，关闭清空。后台只发送白名单运行元数据，不发送用户原文/文件名/URL/凭据；
诊断手动下载独立于统计同意。安装UUID不是个人用户数，不能据此承诺无法关联安装。

## 面向维护者的建议（未实施）

普通用户只选择参与/拒绝；官方发行版未来的统一统计项目应由维护者配置和运营。
自托管管理员可禁用或覆盖接收配置；不要求每个用户创建分析平台账户或额外部署分析栈。
未来接入前明确接收方、字段、安装ID、保留期限及网络IP日志处理；默认关闭保留。
不要在未同意时收集、自动采页面/会话回放，也不以参与统计作为使用功能的条件。
更换接收方或扩大字段不自动沿用旧同意，需另行定义迁移与同意策略。

小团队可先考虑维护者持有的托管分析项目，后续需要控制入口时再引入自有接收代理。
统计只能观察选择参与的安装，不代表全部用户，也不能单独证明付费意愿。
开源核心+托管服务、团队/企业能力或支持是商业化候选，不是本轮新增需求；账户、
付费、企业权限仍在当前范围之外，不借修复开关隐式引入。
