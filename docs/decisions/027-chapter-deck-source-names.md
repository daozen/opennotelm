# 027 · 章节 Deck 的书籍名称与目录序号

日期：2026-10-04。细化026的来源命名，用户要求“书籍名称-章节序号-章节名称”。

新建Deck选择“使用资料 / 章节名称”时，单章节命名为资料名称-目录序号-章节名称。
整份资料仍使用资料名称，AI拟名和手动改名保留自己的契约。合并多章节仍不适用
单来源命名选项；分别生成按每份章节范围独立命名。

目录序号依据完整目录同级顺序，从1开始，嵌套为1.1、1.2、1.2.1。
不根据本次选择重新编号，不把PDF页码或包含文档/页面节点的原始ordinal当章节序号。
EPUB使用真实nav/NCX顺序和层级，优先于正文spine顺序；PDF使用书签树，Word使用标题树。
保留原目录标题（包括原本含有的数字），不依赖模型推断或删除可能有意义的标题前缀。
非目录节点没有可确认的目录位置时，回退资料名-节点名，不伪造章节编号。

创建时在既有来源快照的chapter对象增加可选number字段，直接保存显示title/export_title。
模型后续规划不能覆盖source名称；PDF下载从当前Deck名称读取，不额外调用模型。
旧manifest缺字段兼容，旧Deck/历史下载/批次重放/停止后继续/副本保留已保存名称，
不自动改历史产物；无需迁移或重建来源、引用、图片/PDF。

章节快照捕获复用Reader可见的EPUB锚点投影，避免只查持久source_nodes而漏掉目录节点；
不把投影写回事实层，ContentBlock身份和CitationSpan offsets保持不变。
生成弹窗说明在12种语言保持一致。

验证入口：test_deck_identity、test_deck_batches、test_chapter_selection，
Deck batches E2E覆盖层级命名、批量/单章一致、来源冻结、刷新和真实PDF下载名。
具体验证及部署结果见[ACCEPTANCE](../ACCEPTANCE.md)。
