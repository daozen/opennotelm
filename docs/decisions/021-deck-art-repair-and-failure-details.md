# 021 — Deck 视觉编排修复与任务失败详情

日期：2026-10-03。状态：已实现；更新 [020](020-deck-generation-reliability.md)
中的作者修复协议及诊断范围，其他事实/出处/并发/缓存约束保持有效。
后续[028](028-multilingual-art-layout-validation.md)修复多语言布局归一化、定位超限页和重复反馈。

## 问题与证据

最新一批三个 20 页 Deck 的文字写作分别有 29、29、28 次请求；额外调用主要用于
结构或阅读预算修复。批量 Deck 仍由单重任务队列依次执行，用户看到的等待时间包含排队，
不能把创建至完成的差值当作单个模型请求耗时或并发性能。

其中一个 Deck 的补页任务连续两次卡在 art_directing。私有副本复现了同一链路：
首次输出的 `pages[0].viewpoint` 使用不支持的选项；第二次合法字段 patch 修正后，
第 7、15 页仍选用了缺乏已写作关系支持的 branching_journey。原先只反馈首个错误，
两次机会用完后，后续业务规则变成通用结构失败，用户难以判断哪个阶段/规则失败。
既有诊断仅有类别和路径，art 字段路径还不在旧白名单中。

## 修复契约

- `diagnose_art` 在 schema 校验失败时也预检独立规则：页顺序、内容支持、表达种类、
  相邻/频率、观察角度、文字位置、连续构图与空间布局重复。
- 一次反馈已发现的问题；可定位问题用 FieldValidationError 与稳定 reason code，
  字段 patch 只修改诊断路径，之后重新验证完整 DeckArt 与业务规则。
- art 使用 `DECK_ART_INVALID`；最多三次，第三次仍必须有修复进展，禁止无限重试。
- 无法定位字段时明确要求完整 JSON，不能要求没有路径的空 patch。
- 作者采用 auto repair：少量字段错误请求 patch；整组文字/关系需压缩或没有路径时，
  请求完整单页 JSON，再只合并已诊断字段。长度修复保留原有像素与出处契约。
- 首次作者提示统一目标为预算的 75%，先分配标题/引文/解释空间；正文优先少量完整解释，
  消除“2–4 内容片段”与原先 preferred=5 的矛盾。没有删除全书背景、原图、引申知识，
  没有自动截断引文或放松真实出处校验。

## 失败详情与隐私

Deck 界面按需读取 `GET /api/decks/{id}/diagnostics`，失败时显示“查看失败详情”，
重试成功后仍可“查看生成记录”。支持刷新与 `?download=true` 下载；响应 no-store。

报告只包含当前 Deck 的 job/runs、页号/状态/安全错误码、最近 500 次尝试（界面 50 次）、
时间/耗时、请求结果、token/finish metadata、附图数、HTTP 状态、已知校验规则和字段路径，
以及安全的数值上限/实际计数。单页作者和整页生图关联 subject_id，art 列表下标可转页号。
记录并行 ContextVar 隔离，SQLite 无时区时间明确按 UTC 解释。

结构输出与分段理解捕获安全请求错误；整页生图也记录成功/请求失败与耗时。
这是任务级支持信息，不是全部网络/内部异常的原始 trace。原生兼容路径未新增逐调用 trace。
存储与导出双重白名单，不输出完整异常、源文、拒绝值、模型提示/响应、URL、凭据、未知字段名。
旧记录无法补录具体规则/页归属；界面说明其限制，不猜测历史失败原因。

沿用 migration 017 的 metadata_json，无新增 schema migration；删除 Deck 仍级联其任务诊断。
既有成功 spec/style/art/images/PDF 不自动升级；失败重试复用成功内容。
