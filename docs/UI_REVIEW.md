# UI 与交互审查（2026-10-03）

本轮针对首页、资料与知识列表、问答、阅读、Deck、模型设置、创建/删除/引用/编辑弹窗。
在独立测试实例检查桌面、平板和手机宽度，保留已有数据、引用及生成契约。
测试使用临时资料和模拟模型；这里不评价真实模型的解读或图片质量。

| 发现 | 对用户的影响 | 本轮优化 |
|---|---|---|
| 小屏幕仍堆叠三栏，Deck 后方才有资料和作品列表 | 切换需要滚动很远 | ≤1100px 使用“资料与知识 / 工作区 / 演示文稿”分区导航；面板保持挂载，保留草稿 |
| 打开资料或新 Deck 后仍可能停在列表分区 | 用户找不到刚打开的内容 | 路由目标变化时自动进入工作区；浏览器刷新仍使用既有对象 URL |
| Desktop 的 Studio 没有翻译 | 术语含义不清、跨语言不完整 | 标题改为本地化的“演示文稿”；Visual Deck 保留产品名称 |
| “已索引”“建立索引”偏技术用语 | 不知道资料是否可以提问 | “可用于问答”“准备问答检索” |
| 资料勾选和打开名称的关系没有解释 | 误以为勾选等于打开，或不知道问答范围 | 列表说明勾选用于问答与默认生成，点击名称阅读 |
| 排队/失败知识页都可能显示等待生成 | 不知道任务的真实状态 | 分别显示排队、生成、失败及查看原因提示 |
| 首次列表加载就显示空状态 | 误以为没有资料 | 独立加载提示；读取失败时显示重试，成功后清除读取错误 |
| 问答零资料仍允许发送 | 无意义请求与难理解的失败 | 禁止空所选范围发送并提示选择资料；显式章节范围保持可用 |
| 新消息把整页滚到最下方 | 中断阅读、移动工作区位置 | 仅滚动对话容器，向上阅读时不自动追到最新消息 |
| 新建弹窗标题、示例过于抽象 | 用户不知道应该填写什么 | 明确“创建笔记本”、主题示例及描述用途 |
| 多种模态窗口没有统一键盘行为 | Tab 离开弹窗、焦点丢失、背景可被操作 | 共用 Modal：焦点约束、背景 inert、滚动锁定、Escape、关闭后还原焦点；支持嵌套引用 |
| 删除/复用资料失败提示在背景 | 确认框内看不到原因，可重复提交 | 在当前弹窗显示错误并限制提交中重复操作；删除强调不可恢复 |
| 按钮层级同权，昂贵副本操作紧贴下载 | 容易混淆原地修改与新建副本 | 阅读/下载保留直接入口；重新导出及两种副本进入“更多操作”，解释保留原稿 |
| 停止后的空 Deck 不显示继续提示 | 看不到下一步 | 修正分支，提示点击继续生成 |
| 图标按钮、重试按钮在触屏上过小 | 点错删除或难以点击 | 小屏幕重要按钮及图标至少44px；阅读与列表行配套排版 |
| 帮助/状态浅绿色过淡 | 可读性不足 | 提高主要辅助文案对比度，保留清楚的危险操作色与边框 |
| 按钮不换行、标题/长翻译容易撑开布局 | 手机横向溢出、设置栏拥挤 | 长按钮换行、标题断行、弹窗限高、设置控件自适应 |
| 仅中文和英文、未考虑RTL | 其他语言无法使用，阿拉伯语布局方向错误 | 12套完整本地资源、持久语言设置、文档方向和逻辑间距；原文保持自身阅读方向 |
| 设置的旧读取请求晚返回会覆盖用户新选择 | 已选并发数被重置，保存按钮突然禁用 | 读取请求版本隔离，卸载/重复初始化后的旧响应不再回写 |

## 验证入口与范围

- `frontend/e2e/ui-review.spec.ts`：键盘与删除错误、分区与草稿、Reader/Deck
  在320/390/768/1024/1440px、12种语言设置与刷新、阿拉伯语RTL。
- `frontend/src/Modal.test.tsx`：焦点循环、Esc、忙碌状态、嵌套窗口。
- `frontend/src/i18n.test.tsx`：完整语言目录、键与变量一致、草稿及安全错误翻译。
- `backend/tests/test_preferences.py`：各语言保存/重启、隐私偏好独立、无效输入拒绝。
- 现有导航、引用、章节、知识、Deck生成/编辑/停止/重试/删除浏览器回归继续执行。

具体测试结果见 [ACCEPTANCE](ACCEPTANCE.md)。截图保留在本地测试输出，不提交真实用户内容。
平板/手机检查是浏览器视口模拟，尚未构成真实 iPad、移动 Safari 和所有屏幕阅读器的
设备认证；翻译采用模型辅助并校验资源完整性，后续可由母语贡献者改进措辞。
