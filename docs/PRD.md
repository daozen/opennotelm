# OpenNoteLM 当前需求定义

更新日期：2026-10-04。实现范围为 `769f463` 基础及 decisions 030–036 增量。
软件包版本仍为 `0.1.0`；本文不意味着已正式发布新版本。

本文是当前产品需求契约。原始需求完整保存在 [v0.1 归档](archive/v0.1/PRD.md)，
对应变更和决策见 [需求差异表](REQUIREMENTS_CHANGES.md)。
实现细节见 [系统设计](SYSTEM_DESIGN.md)，交接入口见 [HANDOFF](HANDOFF.md)。
后续明确用户要求优先；未实现的能力必须单独标记，不能用本文代替验收。

## 1. 产品目标与不变原则

开源、本地优先、单用户自托管的 AI 知识工作台。唯一顶层对象是 Notebook：

```text
Notebook → Sources / Chat / Knowledge / Studio（Visual Deck）
Source → Understand → Chat → Knowledge → Visualize → PDF
```

1. 原始 Source 是事实来源；AI 识别、理解和生成内容不得冒充原始文件。
2. 引用必须回到 Source、ContentBlock 和精确字符范围，不能指向 Chunk 或摘要。
3. 检索索引、阅读投影和可重建的理解缓存不是事实层。
4. Knowledge 是用户主动积累的理解；Deck 是面向任务的产物。
5. 无账号、外部数据库、Redis 或独立向量服务要求。用户自行配置模型并承担调用成本。
6. Deck 不套固定 PPT 模板；整体视觉语言统一，页面表达应有变化并服务于理解。
7. 用户需求优先于默认表现偏好，事实真实性、数据安全和接口技术限制仍是硬约束。
8. 本地优先不等于推理离线：使用外部模型时，会发送相关资料及原图。

## 2. 当前支持范围

| 能力 | 当前要求与实现边界 |
|---|---|
| 资料 | 多选上传 EPUB、文本/扫描/带图 PDF、Word `.docx`、Markdown、TXT；单个/批量 URL 网页正文 |
| Word | 正文、标题、列表、表格、内嵌栅格图片；不承诺完整 Word 排版还原 |
| 文档图像 | 保留原图预览，使用支持图片输入的语言模型识别文字、表格与图示关系 |
| 阅读 | 目录/章节、上下章节、PDF 独立页码跳转、可读正文、原图与识别结果 |
| 问答 | 在所选资料内检索并回答，证据不足明确提示；可追溯原文段落 |
| Knowledge | 全 Scope 分层生成、编辑、主动增量更新、引用、从问答保存 |
| 临时转换 | Summary/Outline 等，用户主动保存为 Knowledge |
| Deck | 10/15/20 页，合并或分别生成、树状章节选择、模型解读、内容自适应风格 |
| Deck 生命周期 | 阶段进度、部分成功、重试、停止/继续、任意状态删除、单页修改 |
| PDF | 新 Deck 为整页图像 PDF；旧原生 Deck 保留可选文字的原生导出路径 |
| 界面语言 | 简/繁体中文、英、日、韩、西、法、德、巴西葡语、俄、阿拉伯语、印地语，即时切换并持久保存 |
| 部署 | Docker 单命令、自托管数据目录；本机或可信内网浏览器访问 |

仍不支持：旧版 `.doc`、PPTX 导入/导出、YouTube/视频导入、第三方资料库连接器、
云账户/同步/团队权限、Web Search、Deep Research、Agent/MCP/工作流引擎、自动 Wiki、
知识图谱、音视频产物、原生移动应用、插件市场及 Canva 式编辑器。
手机和平板可以使用响应式网页；公网远程访问与认证隧道尚未成为内置产品能力。

## 3. Notebook 与模型设置

首页支持创建、重命名、删除及打开 Notebook；显示资料、Knowledge 和 Deck。
Notebook 工作区保留资料/知识、阅读/问答、演示文稿的信息结构；1100px及以下通过分区导航切换，保留草稿。
Sources 勾选代表 Notebook 问答和默认生成可用的资料，不增加独立 Context Manager。
删除 Notebook、永久资料或 Deck 等破坏性操作应清楚展示对象与后果。

三个全局 OpenAI-compatible 模型角色分别为 Language、Embedding、Image，
不做每 Notebook 模型覆盖。模型发现失败时允许手填 Model ID。
设置保存前测试语言文本/JSON、Embedding 向量/维度和图片生成能力。
图片输入另有语言模型能力测试；文本/JSON 测试通过不等于支持识图。

Embedding 仍用于当前索引和 Chat 检索，普通文本生成模型不能直接替代 `/embeddings`。
解析阅读及全 Scope 的 Knowledge/Deck 理解不采用普通 Top-K 检索作为全部输入；
不能因此把现有 Setup 的三角色配置要求改写成“Embedding 可在 UI 中省略”。

更换 Embedding 模型、服务地址或向量维度并测试保存后，自动重建当前各 Notebook 中
已解析且有文字的资料索引；共享资料只处理一次，不自动发送已解绑资料。仅更换密钥或
重复保存相同有效配置不重新计算。模型设置的“资料检索索引”显示整体和逐份的排队、
进度、可用与失败状态，支持重建待处理项、重试失败项；关闭设置或服务正常重启后继续。
同名模型在服务端实际换权重时，可在更多操作中显式“重新计算全部索引”。
重建会发送已解析文字给所配置的 Embedding 服务，可能产生费用；只更新检索层，
不重新解析/OCR，不修改原始文件、ContentBlock、引用、历史问答、Knowledge 或 Deck/PDF。
失败保留原索引；旧模型索引不能用于新模型问答，未完成资料会提示在模型设置中查看进度。
连续换模型时同一资料保留唯一活动任务，丢弃过期计算结果并继续最新配置；已经完成的
资料无需陪同失败项重新处理。升级本身不换模型或自动重建。详见 decision032。

### 任务与模型并发配置

| 设置位置 | 用途 | 范围 | 默认 |
|---|---|---|---|
| 语言模型 → 图片识别并发数 | 导入或重新识别文档图片 | 1–20 | 4 |
| 语言模型 → Deck 内容生成并发数 | 独立资料分段理解、逐页写作 | 1–20 | 2 |
| 图片模型 → 图片生成并发数 | 最终整页图片生成 | 1–20 | 2 |
| 模型设置 → 同时处理任务数 | 资料、Deck、知识及问答任务共享执行额度 | 1–8 | 3 |
| 模型设置 → 每个模型服务的总请求并发数 | 相同服务地址的所有模型角色共享请求额度 | 1–20 | 8 |

分别保存，无需重新测试模型或修改密钥。1 为串行；保存后在下一次任务开始时生效，
运行中的任务保持三项内部并发的开始时设置；同类重操作跨任务共享额度，不按任务数量叠加。
不同实体可并行处理，但同一资料/Deck操作及资料写入与读取不能相互覆盖。
任务类别轮流获得空闲位置，避免大批Deck挤占资料或问答；同一资料的读写保留排队顺序。
任务总额度下降不停止现有任务；服务请求总额度变化用于后续请求，已发请求继续完成。
模型服务按协议/主机/端口归组，同地址不同API路径/模型角色仍共享上限；不同别名不自动合并。
20 是配置上限，不是承诺每个模型服务均能承受 20 个并行请求。

## 4. 资料导入、原图及识别

多文件上传最多三份同时发送，各项成功/失败/重复单独显示。后台不同文件可以同时解析；
解析线程取消后等待释放原文件。网页原图保存与识别采用流水线，下载超时只覆盖下载阶段；
成功原图/识别缓存仍可重用。Embedding最多两批请求并行，每批32项，保持输入顺序并原子
替换索引；任一批失败保留原索引。同书章节首次背景理解单飞，取消等待者不影响其他章节。

上传文件保留原始字节、校验和与稳定身份；重复文件可链接到另一 Notebook，
不重复解析/向量化。多选上传每批最多 50 项，逐项显示结果、失败可重试，重复资料逐项确认。格式限制、压缩包和图片解码限制在配置/解析器中执行。

- EPUB 保留 Spine、TOC、章节及段落语义，防止不安全路径和外部资源访问。
- PDF 保留文本层、页码和原生书签；低文本页使用本地渲染后识别，
  提取的栅格插图和符合检测条件的矢量页面也可进入识别。
- Word `.docx` 使用安全的 OOXML 解析；不执行字段、脚本或外部图片关系。
- Markdown/TXT 保留标题、列表、表格、代码及段落等适用语义。
- 网页 URL 每行一项，最多 50 项，保存原始 HTML 和来源/时间，提取正文、标题、列表与表格。
  支持公开 HTTP(S) 页面；不携带登录态或执行脚本，不承诺动态/登录页面成功。
  导入时可选“保存正文图片”（默认勾选），正文先可用，后台保存原始栅格图并受控识别。
  取消勾选仅保留文字说明；旧网页可显式补图。逐图失败不阻断正文，原图可预览/下载，
  识别结果及原图供问答、引用和 Deck 理解复用；数量/大小/超时有限制，复杂页面可能漏图。
  同一 URL 复用保存快照，解析/索引重试不改写原文。错误与原始文件导入均进入现有资料状态/重试流程。

识别使用语言模型，忠实抄录原语言可见内容并描述图示关系。
Reader 同时显示原图和标注为 AI 识别的内容，不能把模型识别等同于原图事实。
失败/不确定状态应可见，可重试；成功部分保留，不因一个图片失败全部重跑。
纯扫描资料无可用文字时明确失败并保留原图，不能假装成功地给出低质量正文。
复杂图表、手写及低清扫描的准确性取决于模型，用户应可对照原图。

已有资料不会仅因升级自动发给模型。用户可主动“识别文档图片”补充解析。
已有原生文字 block 身份和偏移保持兼容；内容变化后原检索索引失效并重建。
成功识别结果可复用，不因调整并发或更换模型自动改写为另一份事实文本。

## 5. 阅读、目录与导航

PDF 即使由逐字绘制的文本片段构成，也应以可读的行/段落显示。
阅读投影不得改写事实 block 或使历史引用失效；无法精确对齐时回退已有内容。

目录来源为真实 EPUB TOC/章节、PDF 书签、Word 标题或文本作者标题。
没有书签的 PDF 不把每页、推测的绘制标题当作目录；提供独立的前后页与页码输入。
有章节时提供顶部和底部的上一章/下一章，到边界禁用，底部翻章后定位新正文。

Notebook、资料/章节、Knowledge、Deck/页均有可刷新、可分享的 URL。
浏览器刷新、前进/后退和新标签应恢复目标对象与可编码的 Scope。
Deck 用稳定 slide ID 定位，不以可变化的页序代替身份。
未保存的 Knowledge/页面编辑离开前有保护；删除对象或失效链接给出可恢复入口。
URL 定位不承诺完整草稿在刷新后持久化，也不等于逐像素滚动位置永久保存。

## 6. Chat 与 Citation

Chat 默认只使用当前 Scope 的原始资料，不能套用 Deck 的模型知识引申规则。
支持所选资料、整份资料、单章节及多节点范围；排队后使用冻结的范围。
短 follow-up 复用上一条用户问题作为检索上下文，不增加查询改写模型调用。
证据不足明确提示，不伪造出处或用自身知识补全缺失事实。
笔记本“新内容语言”默认跟随界面，也可指定现有12种语言之一，用于新问答、知识页、
摘要、提纲及Deck初始语言。语言在提交时冻结，排队期间切换界面不改变结果。
仅生成的标题与解释使用所选语言；原文引文、身份与偏移保留，语言设置不放宽资料约束。
已有资料和产物不自动翻译；Knowledge更新保持该页保存的语言。
接口省略输出语言时仍兼容原来的问题/源语言行为，详见[034](decisions/034-content-output-languages.md)。

引用点击后应展示资料、章节/页码、精确引文和相关可读原文段落，并能定位 Reader。
旧的一字引用仍保持精确范围，但补充真实段落上下文，不再只显示一个字。
段落预览由原始 block 投影，不能由 LLM 生成。引用不越过所选章节边界。
无文字描述但有已注册原图的图片可用原图出处，显示空引文而非伪造文字。

资料从 Notebook 移除和永久删除是两件事。永久删除后已有问答、Knowledge、Deck
不应跟着丢失，历史引用应显示原始来源不可用。

## 7. Knowledge 与临时转换

Knowledge 生成读取完整 Scope，长文分段汇总后全局整合，保留原始出处。
支持编辑、从问答保存、用户主动 Update with Source、从 Knowledge 生成 Deck。
更新保留仍被原文支持的既有信息，不因新资料没提到而删除；明确冲突时修正引用。
Summary/Outline 等为临时转换，只有用户主动保存才成为 Knowledge。
没有自动概念提取、后台自动合并、自动交叉链接或知识 Agent。

Knowledge、Chat 与转换仍沿用各自基于资料的策略；Deck 的允许引申规则不自动扩散。

## 8. Deck 创建与批量章节

新建可选择 Scope、10/15/20 页、输出语言、补充说明及生成方式：

- **合并**：所选资料/章节按原文顺序和去重范围生成一份 Deck。
- **分别**：每份资料或每个选中章节范围各生成一份 Deck，独立排队、引用、重试和导出。

目录选择支持树状展开/折叠、父子勾选、部分选中、全选/清空与按目录层级选择。
选中父目录包含整个子树，分别生成时仍为一份 Deck；想逐小节生成应选择小节层级。
父子重叠去重，空/无正文/外部资料节点不能启动，创建前显示份数与总页数。
无目录时选择整份资料。PDF 书签范围目前是页级，同页多个章节不能精确隔离行。
分别生成一次最多 100 份，创建原子且网络重试不重复创建。
可选由 AI 拟定名称或沿用来源名称；后者仅限每份 Deck 使用一份资料或一个章节。
分别生成时按各自资料 / 章节名称命名，知识页范围不适用此选项。
章节来源命名为“资料名称-目录序号-章节名称”，如“示例书籍-4.1-示例章节”。
序号按完整目录同级顺序从1开始，子章节用层级序号，不随勾选范围/顺序重新编号。
目录标题原样保留；整份资料仍使用资料名。AI拟名、用户改名及已有Deck名称不自动改变。

不提供固定主题/配色/字体/模板列表。用户可在补充说明中指定视觉风格与讲解要求。
页数包括封面和结尾；不简单等分资料，不自动突破用户选择的页数。

## 9. Deck 的解读与用户意图

理解资料时即使用补充说明，不能等到最后生图才加入要求。
允许调用模型知识解释核心思想、关键概念、隐喻、论证联系和适当类比，
尤其当用户要求深入、通俗、逐段解读时；不能仅把原文换词或加长概述。
用户要求“只依据原文”时，不添加外部背景和虚构例子，但可以细读并分析原文。

默认不加入“作者见解”“作者观点”“解读边界”“阅读边界”等生硬标签、
泛化警告与额外免责声明；这不禁止有价值的解释，也不删除原文自身的限制。
用户明确要求补充评论/边界时可覆盖该展示默认。

优先级为：事实真实性和安全/技术硬约束 → 用户明确要求（单页修改更具体）→ 默认偏好。
原文、图片文字、旧摘要/计划都是数据，不是新指令。
补充说明不能自动改变显式 Scope、页数或输出语言；新要求需要调整对应创建参数。

内部区分原文、贴合原文的解读、模型背景与类比。原文/解读引用实际提供的出处；
背景和虚构例子不伪装成原文，不显示内部分类名作为页面标签。
引文、数字、说话人和事件时序应准确，不编造来源或引用。
引用结构校验不等于每一条模型解释都经过语义事实验证。

### 自动整本书背景

从单章/多章生成时，自动理解所属资料的全书正文，并结合目录、章节位置与全书摘要。
选中章节仍是主体，其他章节的信息有自己的出处；不把其他 Notebook 资料自动纳入。
首个章节读取长书有额外模型调用，后续相同资料的章节可复用摘要。
不是每页重发整本书，也不保证摘要涵盖每个细节。
明确要求“不联系全书、只解读本章”时跳过；“只依据原文”本身不等于禁止全书资料。
已完成 Deck、停止后继续及视觉副本不自动重读；标准页数的重写内容副本使用新理解机制。

### 原图理解

Deck 资料理解和全书阅读会分批直接读取原图，并结合识别文字，而非只靠 OCR 摘要。
相关页写作再次对照该页出处对应原图，保留图表结构与空间信息。
没有文字的已解析图片也可作为视觉证据；无法获取所需原图时明确报错。
首轮读取每组至多四张，并受上下文预算限制；页写作也至多四张相关原图。
最终生图仍按文字提示重新绘制；**尚不直接嵌入或精确保留原图**。

## 10. Deck 视觉、预览、编辑与 PDF

内容、目的、受众、语气和用户风格要求共同决定视觉语言。
模型自由提出内容相关的方向并选择，不从固定主题库按题材匹配；
不同内容应能使用适合的媒介，不能默认暖纸插画，也不要求随机制造差异。

整套风格统一，页面表达按内容变换。生图前统一编排表达形式、文字位置、
尺度与必要的视角；依据已有语义约束拒绝不支持的图表/箭头及过度重复。
“解释形式”词汇不等于固定视觉模板；平面风格无需强制立体透视或明暗交替。
模型是否真正遵循风格、文字是否正确，仍需检查真实输出。

新 Deck 默认由图片模型生成同时含图片和文字的完整页面。应用保留可编辑文字稿与出处。
默认 PDF 为整页图片，不具有可搜索/复制的正文文字层；不能宣称原 v0.1 文字层要求已满足。
旧 `native` Deck 保留原生渲染与文字层，不在升级时偷偷转换。

预览缩略图与大图独立滚动；选择页重置右侧内容位置。正常预览约一屏高，
最小 520px；平板优先 Deck，手机使用紧凑缩略图。专注预览占据视口，
支持前后页、页码、Escape 退出及焦点恢复。
普通/专注预览均可点击预览图左半边上一页、右半边下一页，点击区域不显示按钮；
键盘↑/↓分别上一页/下一页，首尾停住不循环。编辑文字、输入控件、弹窗及组合键不触发
快捷切页；切页保持稳定slide ID URL与缩略图同步。“查看高清页”作为独立链接保留。

可展开查看生成时的资料、章节路径及知识页名称与版本，并跳转原文。
新 Deck 保存名称快照；旧 Deck 从保留资料还原并明确说明，来源删除后仍保留已存名称。
空闲 Deck 可重命名；排队/生成中先停止，名称修改不会重绘已生成页面。
下载 PDF 使用当前 Deck 名称，改名后保留已有 PDF 字节与下载可用性。

新 PDF 使用无损压缩减小体积，保持每个图片像素及原始分辨率、书签和兼容文字层。
旧文件不自动改写；“更多操作 → 重新生成 PDF 文件”从既有页图保存压缩版，成功后优先
下载该版，失败仍可下载原版。无需重新生图，压缩比例取决于页面内容。

演示文稿列表支持多选/全选可下载Deck，批量下载为一个ZIP；每份PDF采用当前Deck名称，
重名自动加序号，字节保持不变。仅已有当前版本PDF、文件存在且空闲的Deck可选；不因
下载自动生成或重新导出。任一所选文件已失效/损坏则显示原因，整个请求不遗漏项目。
每次最多100份、512MiB，较大集合分批下载；临时链接最长30分钟有效，容量不足时回收旧的
空闲包，应用重启后可重新打包；已开始下载的文件受保护。
选择和打包机制可供后续其他产物复用，当前仅实现Deck PDF，不新增其他产物类型。

支持文字编辑、内容/视觉/图片重生成、自然语言修改、排序、删除单页。
单页修改不重生成全套；整页图像模式文字修改会重新绘制该页。
“无图片继续”仅适用于原生资产模式；整页模式必须有页面图片。

| 副本操作 | 当前行为 |
|---|---|
| 视觉优化副本 | 保留文字和出处，重新选择风格并编排；原 Deck 不变 |
| 重写内容副本 | 标准页数重新理解/规划/写作并重新选风格；原 Deck 不变 |
| 删页后的非标准页数重写 | 保留既有理解和页面序列，更新写作；不恢复被删页 |
| 继续生成 | 沿原任务、已保存理解/风格/页面继续，不自动刷新提示版本 |

原始 API 视觉副本省略 `restyle` 时仍兼容保留风格；UI 的两个优化副本入口明确请求重新选风格。

## 11. 任务可靠性与数据

长任务显示具体阶段、页标题、进度、成功和失败，不只显示长时间 Spinner。
允许已有结果先查看。分段、计划、文字、图片及 PDF 可在成功后复用；
模型/输入或版本变化时按对应缓存契约判断失效，不大范围清空。

排队中和运行中的 Deck 都能停止，保存进度并保持停止状态直至用户继续。
继续使用原 job/payload；重新启动应用不得自动恢复用户主动停止的任务。
服务意外中断的运行任务可在重启后从保存进度恢复。

任意状态 Deck 可删除；先停止并清理其页面/图片/PDF，保留原始资料与其他 Deck。
单页失败保留成功页，未完成文字时标记 partial，不用后续“缺少内容”错误盖掉原始失败。
修复引用/结构/字数必须有界，保持真实出处并保留有效字段，不无限重试。
视觉编排同时反馈已发现的独立规则问题；少量字段修复避免重新输出整页文字。
布局重复判断保留各语言文字和实际空间数字，不把非英文描述清空；仅页码标签不算布局变化。
确实重复时定位超出限额的页面layout字段，保留其他有效编排、已保存文字和出处。
新失败详情显示受影响页号、重复次数及上限，不回显原始布局/模型输出；历史记录不补造。
失败 Deck 可查看具体阶段、页号、规则/字段、尝试和耗时，并刷新或下载本 Deck 诊断。
重试成功后仍可查看历史生成记录；旧任务缺失的详细规则不能事后猜测补录。

所有业务数据、加密密钥和产物在一个 `data/`。单目录只允许一个应用进程。
升级、备份与回退应保护原始资料、旧产物和密钥，不能以删除用户数据解决失败。

## 12. 安全、隐私与部署边界

文档/图片/模型输出视为不可信。安全解析压缩包，不执行嵌入脚本或获取远程文档图片。
引用 ID、结构字段、布局和文件路径服务端验证；密钥不进正文日志、遥测或浏览器持久存储。
仅环境引用或加密 SecretStore 保存密钥，备份须包含加密主密钥。

匿名遥测默认关闭；明确启用且部署者配置接收服务才发送允许的无内容事件。
用户开关保存参与统计的选择，不因接收服务尚未配置而禁用；显示保存反馈，失败恢复
原选择。未配置时仅本地有界暂存（最多1000条、7天），关闭即清空，不对外发送。
接收地址/项目标识属于维护者或自托管部署者配置，普通用户不需要注册统计平台。
当前发行版不内置维护者统计项目；统一项目接入和商业化方案仍为待决策项。
诊断导出可含错误阶段、耗时、字段路径及 token 元数据，不含资料正文、提示、密钥和响应。

默认本机访问；可信 LAN 可配置监听和允许的 Host。没有登录/RBAC，不能把 LAN 模式
等同于安全公网访问；移动远程控制不是内置公网发布方案。

## UI 与多语言交互

首次使用根据浏览器偏好语言（通常继承系统语言）匹配支持的12种语言；地区变体按
可用目录映射，中文优先区分Hans/Hant，再匹配地区，无法匹配回退英文。手动保存的
语言始终优先，不因升级或更换浏览器覆盖。自动匹配不写固定实例偏好，新内容默认
跟随最终界面语言。详见[035](decisions/035-browser-default-language.md)。

本轮系统审查见 [UI_REVIEW](UI_REVIEW.md)。弹窗支持焦点约束、Escape、背景不可操作和关闭焦点恢复；删除失败在确认框内可见。主要查看/下载操作优先呈现，副本及重新导出在“更多操作”并说明后果。零资料问答提示选择资料。阿拉伯语界面支持RTL；界面切换不翻译用户资料或已生成产物；默认跟随界面的“新内容语言”影响后续提交的新生成。模型配置标签、资料不足系统提示和诊断日期/时长随界面语言显示。
