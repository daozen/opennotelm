## 3. 未完成的发布门槛

这些是验证/产品开放项，不是要 agent 自行扩范围：

- 正式发布前针对新的发布代码重复完整Docker验收；本次阶段42增量已通过。
- 对真实模型生成的每页文字、数字、原文/解读、关系图和视觉适配做评价。
- 用户对解读深度与跨题材风格的验收尚不能由 schema/test 数量代替。
- 确认发布文档明确默认图像 PDF 无搜索/复制文字层、原图最终重绘和无公网鉴权。
- 升级/备份/回退与长期数据引用审计覆盖当前数据版本；准备正式版本号/发布说明。

自动图像文字校对、精确原图嵌入及图像 PDF 的真实文字层是后续候选，尚无实现。

## 4. 后续工程推进方式

按用户的具体目标做 vertical slice：后端、前端、持久化、错误/partial、恢复与测试。
复杂任务先查当前设计/决策和已有 regression，再补对边界有价值的验证。
同步需求差异和接手说明，使用聚焦提交；不要清空用户数据或替换已有产物来验证。
纯文档变更做链接/路径/历史归档校验即可，不需要重跑模型或重启应用。

遵守单用户/单进程/本地优先架构，不提前引入云账户、Redis、外置向量库或 Agent 框架。
明确区分已实现、已测协议、已测容器、真实质量已评价与仍待确认。
